# Consume accepted page inputs

Read the request, existing page and applicable product decisions. When present,
`egbe-docs/product/prd.md` holds requirements, `product/design.md` the visual direction
and `product/pages/homepage/` the page's content/materials. These paths are conventions,
not required parser inputs; use the existing accepted equivalent.

Preserve exact approved strings where specified, factual claims, pricing choices,
destinations and required proof/media. Plan keys and URLs are action metadata, not
visible field labels. A content document's numbering need not become DOM section
boundaries, and routine design details may be completed within the accepted direction.

Determine the scope of each input. A reference design is source material, not automatic
approval of another brand or every application screen. Existing behavior is not always
desired behavior; proposals are not automatically accepted. A material conflict or
missing price/access/behavior decision goes to the caller, not an invented default.

Implement the actual accepted preview and product action, if any. No public preview
does not remove an authenticated/paid product path. Do not add a canned calculator,
new tariff, invented proof or fake interaction because a document template expects it.
Keep useful implementation notes/evidence with the existing task, without regenerating
the product definition or a separate publication receipt.
